# 02 头语义与缓存原理

## 1. 头定义

- 头名：`x-opencode-session`（全小写字面量，代码与文档统一）。
- 头值：当前 `Session.session_id`，即 `session.rs:157-162` 的毫秒 hex 字符串（如 `19b7f2a3c4d`）。
  - 新会话：启动时生成，全生命周期不变。
  - 恢复会话：`load_history` 按文件名 stem 切换后的 ID。
  - `/clear`：不换 ID（只清消息），头的值不变。
- 发送方式：HTTP 请求头，每次模型 HTTP 请求独立设置（`reqwest` 的 `RequestBuilder::header`）。

## 2. 为什么能提高 KV 命中率

- 服务端以前缀缓存（prefix KV cache）复用注意力状态，路由键通常 = f(模型, 会话标识, 历史前缀 hash)。
- 无稳定标识时，网关只能按请求体全文 hash 匹配，工具调用穿插、时间戳/随机数抖动即 miss。
- 有稳定会话标识时，同一会话的增量请求落在同一缓存分片/同一前缀链上：
  `turn_n+1` 的 prompt 前缀 = `turn_n` 的完整上下文，命中率接近 100%。
- 该头只做路由暗示，不参与鉴权，不影响计费与模型行为；服务端不识别时直接忽略（标准未知头容忍）。

## 3. 发送矩阵

| 请求 | 开关开 | 开关关 |
|---|---|---|
| `POST {base}/chat/completions`（非流式/流式） | 必带，值 = 会话 ID | 不带 |
| `POST {base}/responses`（非流式/流式） | 必带，值 = 会话 ID | 不带 |
| `GET {base}/models`（向导查询） | 带（值 = 草稿会话探针或当前会话 ID，见 §4） | 不带 |
| `validate()`（мини `hi` 探测） | 带（经由 chat 通道自动带） | 不带 |
| 非 LLM 请求（更新检查、MCP、文件工具） | 永不带 | 永不带 |

## 4. 边界语义

- 向导验证阶段尚无正式 `Session`：用 `draft` 的开关 + 临时探针值（如 `wizard-<millis>`）发 `validate`，仅为走通缓存路由探测连通性；正式建会话后一律换成真实 `session_id`。
- `GET /models` 在向导 `FetchModels` 路径下由宿主临时 client 发起：同样按开关带探针头；失败不阻塞（查询失败可手输模型名）。
- 值含非法字符时（理论上 hex 不会）：`reqwest` 的 `HeaderValue::from_str` 失败则跳过该头并 `eprintln!` 警告，不让整次请求失败。
- 开关关闭 → 任何路径不得残留该头（`reconfigure` 关开关时必须清掉 client 里的旧值）。

## 5. 与现有 `user` 字段的关系

- `build_body` 的顶层 `"user": "6ba93f8a8d2e"`（`openai.rs:294`）保持不动：它是请求体遥测，与头路由正交。
- 不把会话 ID 写进 `user`：避免污染服务端按 `user` 做滥用限流的维度。
