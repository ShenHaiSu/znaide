# 07 测试计划

## 1. 单元测试（`cargo test`，零网络）

| 用例 | 位置 | 断言 |
|---|---|---|
| 老配置缺键默认关 | `core/src/config.rs #[cfg(test)]` | `serde_json::from_str::<Config>("{}").resolve(…)` → `session_header_enabled==false`；`ProviderDef::default().session_header==false` |
| 字段级合并只"或" | 同上 | 内置 `ollama(false)` + 用户 `{"ollama":{"session_header":true}}` → `all_providers()["ollama"].session_header==true` |
| env 解析 | 同上 | `ZNAIDE_SESSION_HEADER=1/true/yes/on` → 开；`0/false/no/off` → 关；非法值 → 忽略（保留文件值） |
| CLI 覆盖 env/文件 | 同上 | `resolve(…, cli=Some(false))` 压住 env/file 的 `true` |
| 向导换家带开关 | `tui` 单测（仿现有 `apply_config` 测试） | A 家开 → 切 B 家（关）→ `wizard.session_header==false`；`draft().session_header_enabled` 同步 |
| `auth()` 行为 | `core/src/llm` 单测（构造 `RequestBuilder` 的 URL 级断言，或抽 `session_header_value()` 纯函数测） | 关 → 不含头；开 + 空串占位 → 不含头（值未到不发）；开 + ID → 含头且值相等 |
| 非法值容错 | 同上 | 值含 `\n` 时跳过头发请求不断（`HeaderValue::from_str` 失败分支） |

## 2. Mock 集成测试（仿 `core/tests/mock_e2e.rs` 画风）

新增 `core/tests/session_header_e2e.rs`（或并入 `mock_e2e.rs`）：

- 起本地 `axum/hyper` mock 端点：`POST /v1/chat/completions`、`POST /v1/responses`、`GET /v1/models`，把收到的 `x-opencode-session` 回显进响应 JSON 或记入 `Arc<Mutex<Vec<_>>>`。
- 用例：
  1. 开 + chat 非流式：断言服务端收到头且值 = `session.session_id()`。
  2. 开 + chat 流式：同上（SSE 路径经 `chat_stream`）。
  3. 开 + responses 非流式/流式：同上。
  4. 关 + 全协议：断言服务端**没收到**该头。
  5. `load_history` 恢复后：第二段对话的头值 = 老会话 stem，前后值不同。
  6. `reconfigure` 开→关：同一 `Session` 后续请求头消失（不清连接池不断言，只断言头）。

## 3. 回归矩阵（手动，10 分钟）

| 场景 | 期望 |
|---|---|
| 老 `config.json`（无该键）启动 | 无头，对话正常，`/config` 摘要显示"会话头 关" |
| 首启向导全走（开） | 文件落 `true`，状态栏会话 ID = 抓包头值 |
| 首启向导全走（关） | 文件落 `false`/缺键，抓包无头 |
| `/config` 切家 | 开关跟着家变，不串家 |
| `--resume <id>` | 头值切到老 ID |
| `/clear` | 头值不变 |
| `--session-header` / `--no-session-header` | 覆盖文件值当次生效，不写盘 |
| 不识别该头的端点（ollama 本地） | 开着也能正常对话（未知头被忽略） |
