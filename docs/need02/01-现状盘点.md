# 01 现状盘点：初始化 / 配置 / LLM / 会话

> 结论：无任何会话头逻辑，可直接新增。以下均为已读源码验证过的定位。

## 1. 初始化入口

- `crates/cli/src/main.rs:141-150`：`config_provided(&cli)` 判定是否首启；无配置来源 → `first_run=true`。
- `crates/cli/src/main.rs:150-162`：`resolved` 失败时用 ollama 默认值撑住引导界面。
- `crates/tui/src/app.rs:498-516`：首启构造 `SetupWizard` 阻塞对话，`configured_ok=false` 时禁用输入。
- `crates/tui/src/app.rs:1045-1047`：`/config` 重开面板同样 `SetupWizard::new() + prefill()`。

## 2. 向导状态机（`crates/tui/src/config_ui.rs`）

- `Step` 定义 `16-33`：`Provider → Querying → ModelSelect → ProtocolSelect → ApiKey → ContextWindow → MaxTurns → Verifying`，共 7 步。
- 供应商选中 `383-414`：`on_key` 在 `Step::Provider` 回车后记 `self.provider`，换供应商才调 `apply_provider_defaults(name)`，`custom` 走手输端点分支。
- `apply_provider_defaults`（`125-164`）：按 `provider_defs` 快照取该家的 `model / api_key / api_key_env / context_window / protocol`，清模型列表、重置游标。
- `prefill/apply_config`（`168-222`）：从 `Config::load()` 带出全部已存值，`provider_defs = cfg.all_providers()` 快照。
- `draft()`（`262-276`）：拼出未验证的 `Resolved`（`provider_name/model/base_url/api_key/context_window/protocol`）。
- 保存（`crates/tui/src/app.rs:1193-1239`）：`w.draft()` → `cfg.max_turns = w.max_turns` → `cfg.save(provider, model, base_url, key_arg, context_window, protocol)` → `AgentCmd::Reconfigure(draft)` 热生效。
- 步骤条渲染 `684-701`：数组写死 7 项，`current` 按 `Step` 映射，加一步需同步改两处。

## 3. 配置层（`crates/core/src/config.rs`）

- `Config`（`18-44`）：顶层覆盖 + `providers: HashMap<String, ProviderDef>` + `protocol/context_window/max_turns/persona/build_tag`。
- `ProviderDef`（`89-102`）：`base_url/model/api_key_env/api_key/context_window/protocol`，`#[serde(default)]`，缺键向前兼容。
- `Resolved`（`104-115`）：`model/base_url/api_key/provider_name/context_window/protocol`，非 `Option` 的落定值。
- `all_providers()`（`231-263`）：内置表打底，用户条目字段级覆盖（只覆盖 `Some` 字段）。
- `resolve()`（`277-351`）：优先级 CLI > env > 顶层 config > provider 预设；协议链 `cli > ZNAIDE_PROTOCOL > 顶层 > 条目 > Chat`。
- `save()`（`402-435`）：值写进对应 provider 条目，顶层三件套清空；`protocol==Chat` 存 `None` 保持文件干净。
- 内置预设 `builtin_providers()`（`180-227`）：`ollama/dashscope/deepseek/openrouter/zai`，均无 headers 字段。

## 4. LLM 客户端

- 工厂 `crates/core/src/llm/client.rs:59-64`：按 `Resolved.protocol` 分发 `OpenAiClient` / `ResponsesClient`。
- `new_http_client`（`39-51`）：超时 600s + connect 10s + 环境代理，两客户端共用。
- `OpenAiClient`（`crates/core/src/llm/openai.rs:10-15`）：字段 `http/base_url/api_key/model`；`new`（`214-222`）、`reconfigure`（`229-233`）只同步三件套。
- `ResponsesClient`（`crates/core/src/llm/responses.rs:13-18`）：同构四字段；`new`（`427-441`）、`reconfigure`（`442-446`）。
- 头设置唯一点：`auth()`（openai `276-281` / responses `488-493`），仅 `bearer_auth`，无 `.header()` 调用。
- 请求发射点：
  - openai：`list_models`（`244-265`）、`chat`（`307-320`）、`chat_stream`（`324-…`）。
  - responses：`list_models`（`457-478`）、`chat`（`519-532`）、`chat_stream`（`536-…`）。
  - `LlmClient` trait（`client.rs:11-36`）：`model/reconfigure/chat/chat_stream/validate/list_models`。
- 请求体遥测 `REQ_USER="6ba93f8a8d2e"`（openai `18`，`build_body 294` 写入顶层 `user`）：**不动**，与本次头需求无关。

## 5. 会话层（`crates/core/src/session.rs`）

- `Session`（`120-141`）：`llm: Box<dyn LlmClient> + protocol + session_id + history_writer/path + …`。
- ID 生成（`157-162`）：`session_id.unwrap_or(millis hex)`；`--resume` 启动经 `cli resolve_resume` + `app.rs:317-351` 传入已有 stem。
- `load_history`（`375-450`）：按 `path.file_stem()` 切换 `session_id` + `history_path`，作废旧句柄，发 `SessionInfo`。
- `reconfigure`（`211-225`）：同协议走 `llm.reconfigure()`（连接池复用），跨协议重建 client。
- `clear_context`（`261-285`）：只清 `messages` + 截断文件，**不换 `session_id`**（头的值应保持不变）。
- 历史文件懒创建（`165-172, 515-535`）：`~/.znaide/sessions/<id>.jsonl`，首条 meta 行。
