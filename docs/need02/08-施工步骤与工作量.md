# 08 施工步骤与工作量

## 1. 推荐顺序（每步可独立编译通过）

1. **P0 数据模型**（04）：`ProviderDef.session_header: bool` + `Resolved.session_header_enabled: bool` + `all_providers/resolve` + 全工程补构造字段。`cargo check` 即清单。
   - 文件：`core/src/config.rs`（+ `cli/main.rs:154-161` 撑位值 + 所有单测构造）。
2. **P1 客户端注头**（06 §1）：常量 + 字段 + `new/reconfigure/set_session_header/auth`（先 openai，再 responses 镜像），trait 加默认方法。
   - 文件：`core/src/llm/openai.rs`、`responses.rs`、`client.rs`。
3. **P2 会话供给**（06 §2-3）：`Session` 加 `session_header_enabled` + `set_session_header()` + `new/load_history/reconfigure` 调用；宿主建会话点补参。
   - 文件：`core/src/session.rs`、`tui/src/app.rs`、`cli/src/main.rs`（无头路径）。
4. **P3 向导采集**（05）：`Step::SessionHeader` + 字段 + `on_key/render/draft/apply` + 步骤条；`save()` 加参；`app.rs` 保存链路。
   - 文件：`tui/src/config_ui.rs`、`tui/src/app.rs`、`core/src/config.rs`（`save`）。
5. **P4 CLI/env**（04 §4）：`--session-header/--no-session-header` + `ZNAIDE_SESSION_HEADER` + `resolve` 接线。
   - 文件：`cli/src/main.rs`、`core/src/config.rs`。
6. **P5 测试**（07）：单元 + mock e2e + 回归矩阵走一遍。

## 4. 风险与对策

| 风险 | 对策 |
|---|---|
| 布尔合并"关盖不掉开"（04 §1） | 内置全 `false`，首版无碍；文档注明将来转 `Option<bool>` |
| `Session::new` 签名改动漏改无头路径 | 用加参而非默认，靠编译器报错找全建会话点 |
| 探针头（wizard-*) 污染缓存 | 探针值仅用于 `validate` 一次性探测；正式会话立即换真实 ID，文档写明 |
| 某些网关对未知头 400 | 默认关；验收含 ollama 本地开着跑通；真有 400 的家用户可随时关 |
| 步骤条编号与 Esc 回退链断裂 | `current` 映射与每个 step 的 `Esc` 分支逐个检查（05 §3 表） |
