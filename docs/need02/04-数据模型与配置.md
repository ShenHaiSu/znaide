# 04 数据模型与配置

## 1. `ProviderDef` 新增字段（`core/src/config.rs:89-102`）

```rust
#[derive(Debug, Clone, Default, Serialize, Deserialize)]
#[serde(default)]
pub struct ProviderDef {
    pub base_url: Option<String>,
    pub model: Option<String>,
    pub api_key_env: Option<String>,
    pub api_key: Option<String>,
    pub context_window: Option<usize>,
    pub protocol: Option<ProtocolKind>,
    /// 是否为该家启用 x-opencode-session 会话头（默认 false，见 §3 兼容）
    pub session_header: bool,
}
```

- `#[serde(default)]` 已在 struct 级，**老文件缺键自动 `false`**，零迁移。
- `all_providers()`（`231-263`）的字段级合并加一条：
  ```rust
  if v.session_header {
      base.session_header = true;
  }
  ```
  注意布尔合并只能"或"（`false` 无法覆盖内置 `true`）；内置预设全为 `false`，故无歧义。若将来内置某家默认开，再改为 `Option<bool>`。

## 2. `Resolved` 新增字段（`104-115`）

```rust
pub struct Resolved {
    pub model: String,
    pub base_url: String,
    pub api_key: Option<String>,
    pub provider_name: String,
    pub context_window: Option<usize>,
    pub protocol: ProtocolKind,
    /// 本次运行是否发会话头（开关）；具体值由 Session 侧供给
    pub session_header_enabled: bool,
}
```

- `resolve()` 落定逻辑（`277-351`）：`session_header_enabled = cli_override ?? env ?? pdef.session_header`，详见 §4。
- 所有手写构造 `Resolved{…}` 的地方（`cli/main.rs:154-161` 撑位默认值、`config_ui.rs draft()`、单测）必须补该字段，否则编译失败即清单（编译器当检查表用）。

## 3. `config.json` 示例

```json
{
  "provider": "deepseek",
  "providers": {
    "deepseek": {
      "base_url": "https://api.deepseek.com/v1",
      "model": "deepseek-chat",
      "api_key_env": "DEEPSEEK_API_KEY",
      "protocol": "chat",
      "session_header": true
    },
    "ollama": {
      "base_url": "http://localhost:11434/v1",
      "model": "qwen3:8b"
    }
  }
}
```

- 关 = 存 `false` 或缺键（建议显式存 `false`，向导语义明确）；开 = `true`。
- `save()` 签名加一个 `session_header: bool` 参数（见 05 §3），`Chat` 存 `None` 的既有惯例不适用于 bool（bool 无"缺省即默认"的歧义，直接存值）。

## 4. CLI 与 env 覆盖

| 来源 | 形态 | 优先级 |
|---|---|---|
| `--session-header` / `--no-session-header` | 三态：`Some(true)` / `Some(false)` / `None`（clap `ArgAction::SetTrue/…` 或 `bool` + `overrides_with`，以现有 `--protocol` 画风为准） | 最高 |
| `ZNAIDE_SESSION_HEADER` | `1/true/yes/on` → 开；`0/false/no/off` → 关；空/非法 → 忽略并 `eprintln!` 警告（仿 `ZNAIDE_PROTOCOL` 口径，`config.rs:327-335`） | 中 |
| `ProviderDef.session_header` | 文件值 | 低 |

- `resolve()` 新增参数 `cli_session_header: Option<bool>`；`cli/main.rs` 的 `config_provided()` 清单里是否加入 env 名由实现者定（不影响首启判定正确性，加了更准）。
- 无头模式（`-p`）：开关照常 resolve，头值 = 当次无头 `Session` 的 `session_id`（一次命令一值，符合"按会话稳定"）。
