# need02 总览与需求：`x-opencode-session` 稳定会话头

## 背景

部分模型提供商（OpenAI 兼容网关、聚合网关、自建缓存层）用请求头中的稳定会话标识做 KV 复用路由：
同一会话标识 + 增量上下文 → 命中前缀缓存；每次随机标识 → 缓存全 miss。
znaide 现状所有 LLM 请求只发 `Authorization: Bearer`（见 `crates/core/src/llm/openai.rs:276-281`、
`crates/core/src/llm/responses.rs:488-493` 的 `auth()`），无任何自定义头
（`grep x-opencode-session|extra_header|session_header` 在 `crates/` 零命中，已验证）。

## 需求原文（转述）

1. 初始化环节选择供应商之后，选择是否插入 `x-opencode-session` 自生成请求头。
2. 标识符根据会话自动生成、同一会话内稳定。

## 目标（做什么）

- T1：配置层新增按 provider 存储的开关（默认关），`Resolved` 随身携带。
- T2：向导在"选完供应商之后"插入一步是否启用（y/n），`custom` 供应商同样覆盖。
- T3：双客户端（`OpenAiClient` / `ResponsesClient`）统一注入该头，值为当前 `Session.session_id`。
- T4：会话恢复（`--resume` / `load_history`）、`reconfigure`、`/clear` 语义下头的值正确跟随。
- T5：CLI + env 可覆盖开关；`/config` 重开面板可改开关并即时生效。

## 非目标（不做）

- 不做通用自定义头表（`extra_headers: HashMap`）：首版只做一个布尔开关，避免向导复杂化；数据模型预留扩展位（见 04 §5）。
- 不做跨重启稳定的长效设备 ID：头的值 = 会话 ID，新会话即新值；resume 接上老会话则沿用老 ID。
- 不把会话头塞进请求体（`user` 字段不动，`REQ_USER` 保持原值）。
- 不改 `GET /models` 以外的鉴权逻辑；`Bearer` 优先级不变。

## 核心决策一览

| # | 决策 | 结论 | 理由 |
|---|---|---|---|
| D1 | 开关粒度 | **按 provider 条目存**（`ProviderDef.session_header: bool`），与 `protocol` / `context_window` 同口径 | 切 provider 时开关跟着走，避免" A 开了、B 被动带上" |
| D2 | 默认值 | **关（`false`）** | 零回归；老配置无键 → 关；只有用户显式选"是"才发头 |
| D3 | 头的值来源 | **`Session.session_id`**（毫秒 hex，老逻辑不变） | 会话内天然稳定；resume/load 时已沿用 stem；无需新增 ID 体系 |
| D4 | 值的注入时机 | Session 创建/恢复后 `push` 进 client，而非 `Resolved` 里带具体值 | `Resolved` 是"配置快照"，`session_id` 是"运行时身份"，分层清晰；`reconfigure` 不丢连接池 |
| D5 | 发送范围 | `POST chat/completions`、`POST /responses`（含流式）必带；`GET /models`、`validate()` 随开关也带 | 向导验证阶段即走缓存路由，与正式对话一致；`GET /models` 带头无副作用 |
| D6 | 头名大小写 | 统一小写字面量 `x-opencode-session` | `reqwest::header::HeaderName` 对大小写不敏感，但代码与文档统一小写 |

## 验收标准

- A1：全新初始化选供应商后出现"是否启用会话头"一步，选"是"后 `config.json` 对应 provider 条目出现 `"session_header": true`。
- A2：老配置（无该键）加载、resolve、发请求行为与改前一致（不发头）。
- A3：启用后同一会话内 chat 非流式 / 流式 / responses 非流式 / 流式 / validate 发出的 HTTP 请求头均含同一 `x-opencode-session`，值等于状态栏会话 ID。
- A4：`--resume` 恢复老会话后，头的值切换为老会话 ID；`/clear` 不换头的值（会话 ID 不变）。
- A5：`cargo test` 全绿；新增 mock 断言头测试覆盖双协议。
