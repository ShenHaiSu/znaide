# 06 — 会话引擎改造

> 目标：`Session` 全程只认 `LlmClient` trait + `AssistantReply`，主循环、工具执行、历史、中断、用量统计**一字不动**。

## 6.1 持有 trait 对象

```rust
// session.rs
pub struct Session {
    llm: Box<dyn crate::llm::LlmClient>,   // 原 OpenAiClient（L121）
    …
}
impl Session {
    pub fn new(
        llm: Box<dyn crate::llm::LlmClient>, // 签名变（原 llm: OpenAiClient，L144）
        …
    )
}
```

调用点（共 3 处）：
- `cli/main.rs` L275 `run_headless`：`let llm = build_llm_client(resolved)?;`
- `tui/app.rs` L301（`spawn_agent`/`Session::new` 处）：同上。
- 单测/mocks：`mock_e2e.rs` 里构造 `Session` 的地方，把 `OpenAiClient::new(&resolved)` 包成 `build_llm_client(&resolved)`（resolved 的 protocol 为 Chat 时行为一致）；或直接 `Box::new(OpenAiClient::new(&r)?)`——trait 对象兼容，无需改逻辑。

`use crate::llm::OpenAiClient`（L4）改为 `use crate::llm::LlmClient`；`AssistantReply` 的引用（L739：`AssistantReply {…}` 中断构造）改为 `crate::llm::openai::AssistantReply`（类型本身不动地方，只是 import 路径变；也可从 `llm` 重导出保持原名零改动——推荐在 `llm/mod.rs` 加 `pub use openai::{AssistantReply, StreamEvent};` 现状已有 `pub use openai::OpenAiClient`，顺手补一行，session.rs 几乎不用改 import）。

`chat_stream` 回调签名：trait 定为 `&mut dyn FnMut(StreamEvent)` 后，session.rs L725 的闭包 `|evt| {...}` 照常传（自动由 `&mut` 接收），循环体内 `content_buf`/`reasoning_buf`/`cancel`/`select!` 全部不动。

## 6.2 `run_turn_inner` / `compact`：零改动

- L719–752：`self.llm.chat_stream(&self.messages, Some(&defs), …)` 与 `self.llm.chat(&self.messages, Some(&defs))`——方法名、参数、返回类型全与 trait 一致，**无需改行**（dyn 调度自动按实际协议走转换）。
- L754–763 usage 累计：`reply.usage` 已是转换后的 `prompt_tokens/completion_tokens`，UI 事件 `SessionEvent::Usage` 不动。
- L320 `compact_context`：`self.llm.chat(&sum_msgs, None)` 无工具摘要请求，Responses 版自动走 `instructions + input` 转换；返回 `content` 取摘要，不动。
- `finalize_assistant` / `repair_tool_chain` / `record` / jsonl：`ChatMessage` 操作，不动。

## 6.3 `reconfigure` 与"中途换协议"

```rust
pub fn reconfigure(&mut self, resolved: &crate::config::Resolved) {
    // 若协议变了：内存历史仍是 ChatMessage（协议无关），下一次请求会自动按新协议转换——正确。
    // 但正在流式中的请求仍走老客户端：把协议切换做成"换客户端"而非"调 reconfigure"。
    self.llm = build_llm_client(resolved).unwrap_or_else(|_| self.llm …); // 错误时保持旧客户端
}
```

问题：`build_llm_client` 返回 `Result`（`reqwest::Client::builder().build()` 理论可错），而 `reconfigure` 现签名无返回值。方案：
- (a) `reconfigure` 内部 `match build_llm_client`，失败则 `eprintln!` + 保留旧客户端（构造失败概率极低，开关代理配错时才发生；且旧客户端仍可用，属安全降级）。
- (b) trait 的 `reconfigure(&mut self, cfg)` 保留（同协议热换端点/key/model 仍走它，零开销），`Session::reconfigure` 先比较"新旧协议是否相同"：相同 → `self.llm.reconfigure(resolved)`；不同 → 重建 Box。
- 需要 `Session` 记住当前协议：加字段 `protocol: ProtocolKind`（`new` 时由调用方传入或从初建客户端的 `model()` 推断——最干净的是 `Session::new` 加 `protocol` 参数；调用点 3 处顺手传 `resolved.protocol`）。

UX：换协议后内存历史格式不变，继续对话正确；但仍建议在配置保存成功后推一条 `Notice`："协议已切换为 response，历史继续有效；若模型表现异常可 /clear 开新上下文。"（app.rs L1218 的 `MsgItem::Notice` 处追加半句）。

`--resume` 恢复：jsonl 里是 `ChatMessage`，与协议无关；恢复后按**当前配置**的协议发请求——正确且无需迁移。

## 6.4 错误文案（`describe_request_error`）

session.rs 尾部 `describe_request_error(&e)`（run_turn L650 用它转中文提示）：加两条 Responses 相关解读（字符串匹配服务端透传文本，启发式即可）：
- 含 `function_call_output` / `call_id` / `input` 关键字 + 400 → "Responses 请求被拒绝：可能是工具结果(call_id)与调用对不上，或端点不支持当前字段。切回 chat 协议试试（/config 里改协议）。"
- 含 `instructions` + 400 → "该端点不支持 instructions 字段：换 chat 协议，或告诉我端点名字，我加兼容。"
其余（超时/连不上/401/404）与 chat 共用已有文案（传输层错误与协议无关）。

## 6.5 `validate` / `probe_chat`

- `LlmClient::validate`：chat 版保持 `chat([user("hi")], None)`；Responses 版 `chat([user("hi")], None)`（经转换得到最小 Responses 请求）。"成功即算可用"的语义两边一致。
- `probe_chat(probe: &Resolved)`（openai.rs L509）：改为 `build_llm_client(probe)?.validate().await`（按协议自动分流；app.rs L978 调用点不动）。
- `probe_models`：不动（`GET /models` 与协议无关）。

## 6.6 状态栏/统计：不动

- ctx 占用条（`ctx_window = current_resolved.effective_context_window()`）：窗口语义与协议无关（Responses 的 `input_tokens` 即 prompt 侧），不动。
- Token 统计（`tokens_in/out`）：`Usage` 已归一，不动。
- 退出统计、`/usage` 等：不动。
