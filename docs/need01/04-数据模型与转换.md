# 04 — 数据模型与转换

> 核心原则（D4/D5）：`ChatMessage` 仍是内存 + 落盘唯一格式；Responses 语义只存在于"发请求前一刻的转换"与"收响应时的解析"。

## 4.1 `ChatMessage → (instructions, input)` 映射表

函数：`chat_to_response_input(messages: &[ChatMessage]) -> (Option<String>, Vec<serde_json::Value>)`

| 内存 `ChatMessage` | `instructions` / `input` 项 | 备注 |
|---|---|---|
| 首条 `system`（`messages[0]`，`Session` 恒保证） | `instructions: content`（顶层字符串） | 只取首条；若 `messages` 为空或首条非 system 则 `instructions=None`。后续 system（理论上无）按普通项转为 `{role:system,…}`（部分端点支持 system role；不支持的端点会 400，见 §4.3 降级） |
| `user{content}` | `{role:user, content: str}` | `content=None` → 空串（不应发生，防御） |
| `assistant{content, tool_calls=None}` | `{role:assistant, content: str}` | `content=None` 且无 tool_calls（空 assistant，不应发生）→ 跳过并记 `debug!`（若无日志设施则静默跳过，与 `finalize_assistant` 保证"assistant 必有内容或工具"对应） |
| `assistant{content, tool_calls=[…]}` | 先 `{role:assistant, content}`（content 为空则**省略 content 键**，只发 role），再逐个 `tool_calls` 发 `{type:function_call, call_id, name, arguments}` | `arguments` 原样透传（已是 JSON 字符串，不二次转义）。`id` 为空（防御）→ `call_{name}`（与 `value_to_tool_call` 回落一致） |
| `tool{tool_call_id, content}` | `{type:function_call_output, call_id: tool_call_id, output: content}` | 紧跟在它对应的 `function_call` 之后（天然顺序：`record` 总是先 assistant 后 tool，见 `run_turn_inner` L764/L795）。`output` 为空 → 空串（不省略，Responses 要求 output 必填） |

伪代码：

```rust
pub fn chat_to_response_input(messages: &[ChatMessage])
    -> (Option<String>, Vec<serde_json::Value>)
{
    let mut instructions = None;
    let mut input = Vec::new();
    for (i, m) in messages.iter().enumerate() {
        if i == 0 && m.role == Role::System {
            instructions = m.content.clone();
            continue;
        }
        match m.role {
            Role::System => input.push(json!({"role":"system","content": m.content.clone().unwrap_or_default()})),
            Role::User => input.push(json!({"role":"user","content": m.content.clone().unwrap_or_default()})),
            Role::Assistant => {
                if let Some(tcs) = &m.tool_calls {
                    if let Some(c) = &m.content {
                        if !c.is_empty() { input.push(json!({"role":"assistant","content": c})); }
                        else { input.push(json!({"role":"assistant"})); }
                    } else {
                        input.push(json!({"role":"assistant"}));
                    }
                    for tc in tcs {
                        input.push(json!({
                            "type": "function_call",
                            "call_id": tc.id,
                            "name": tc.function.name,
                            "arguments": tc.function.arguments,
                        }));
                    }
                } else {
                    input.push(json!({"role":"assistant","content": m.content.clone().unwrap_or_default()}));
                }
            }
            Role::Tool => input.push(json!({
                "type": "function_call_output",
                "call_id": m.tool_call_id.clone().unwrap_or_default(),
                "output": m.content.clone().unwrap_or_default(),
            })),
        }
    }
    (instructions, input)
}
```

边界：
- `reasoning_content`：内存 assistant 的思考内容**不发**（Responses 的 reasoning 由服务端管理；chat 侧 `build_body` 同样不发 `reasoning_content`——对齐）。
- 中断占位 `PLACEHOLDER_TOOL_REPLY`：普通 output，如实发送（§2.5）。
- 孤儿 tool（`repair_tool_chain` 已保证落盘无孤儿；内存中新产生的孤儿在 cancel 分支已补占位，L796–799）→ 转换层无需再处理。

## 4.2 `ToolDef → Responses tool` 映射

```rust
pub fn tool_defs_to_response_tools(tools: &[ToolDef]) -> serde_json::Value {
    tools.iter().map(|t| json!({
        "type": "function",
        "name": t.function.name,
        "description": t.function.description,
        "parameters": t.function.parameters,   // 原样透传（含 required）
    })).collect()
}
```

- `strict`：首版不发（部分兼容端点不支持；chat 侧也没发）。预留见 §4.4。
- MCP 工具（`mcp__<server>__<tool>`）：名字含 `__`，Responses 侧无特殊限制，原样透传（若某端点对 name 字符集挑剔，400 文案会透出，按 §2.6 处理）。

## 4.3 降级与容错（兼容端点 reality check）

| 风险 | 对策 |
|---|---|
| 端点不支持 `instructions` | 首版照发（标准字段）；若实测某兼容端点 400，在 `describe_request_error` 加提示（见 06 §6.4），二期再加"失败时自动把 instructions 并入 input 首条 system 重试" |
| 端点不支持 `role:system` 的 input 项 | 同上：首版只保证"首条 system 走 instructions"，非首条 system 本就不存在（`Session` 只在 `messages[0]` 放 system） |
| 端点返回超集字段（如 `output[].status`、`encrypted_content`） | 解析层忽略未知键（serde_json::Value 手工取，不用强类型 struct —— 与 `parse_chat_response` 同策略，避免"多一个字段就全挂"） |
| `arguments` 非字符串（对象） | `match String→原样 / 其他→to_string()`（照抄 `value_to_tool_call` L111–115） |
| 流式 `item_id` 缺失 | 回落 `output_index` 定位（`push_delta` 以 `output_index` 为准，`item_id` 仅做一致性校验，不一致时信任 `output_index`） |
