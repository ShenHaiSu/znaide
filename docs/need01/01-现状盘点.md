# 01 — 现状盘点（chat 链路逐文件）

盘点范围：与"协议"相关的全部触点。结论：**只有 `crates/core/src/llm/openai.rs` 是协议相关的**，其余层（config / session / tui / cli）都只认"文本 + ToolCall + Usage"这一与协议无关的中间表示——这就是"尽量复用"的立足点。

## 1.1 `crates/core/src/llm/types.rs`（协议无关，复用）

- `Role::{System,User,Assistant,Tool}` + `ChatMessage{role,content,tool_calls,tool_call_id,reasoning_content}`：内存 + jsonl 落盘的统一格式。
- `ToolCall{id,call_type,function:{name,arguments:String}}`：`arguments` 恒为 JSON 字符串（对象形已在解析层序列化，见 openai.rs `value_to_tool_call`）。
- `ToolDef{type:"function",function:{name,description,parameters}}`：`ToolRegistry::builtin().defs()`（`tools/mod.rs`）+ skill 入口 + `mcp.tool_defs()` 三路合并后传入。
- `Usage{prompt_tokens,completion_tokens}`：`total()` / `is_empty()`。
- **改造点**：零。Responses 层只新增"转换函数"，不改这些结构（D4/D5）。

## 1.2 `crates/core/src/llm/openai.rs`（唯一的协议相关文件，约 719 行）

| 构件 | 位置 | 协议相关度 | 复用结论 |
|---|---|---|---|
| `OpenAiClient{http,base_url,api_key,model}` | L8–13 | 构造与鉴权通用 | 抽取共享构造（超时 600s + connect 10s + `proxy_from_env`）供两客户端用 |
| `REQ_USER` | L16 | chat 请求顶层 `user` 字段 | Responses 不用；各客户端自带常量 |
| `AssistantReply{content,reasoning_content,tool_calls,usage}` | L20–26 | **协议无关的中间表示** | 原样复用：`ResponsesClient` 也返回它，`Session` 零感知 |
| `StreamEvent::{TextDelta,ReasoningDelta}` | L30–35 | 协议无关 | 原样复用 |
| `extract_usage` | L42–49 | chat 字段名（`prompt_tokens/completion_tokens`） | Responses 版读 `input_tokens/output_tokens`；各写一个 5 行函数，不强行抽象 |
| `parse_chat_response` / `content_text` / `value_to_tool_call` | L52–136 | chat 强相关 | 保留不动；Responses 写对等的 `parse_response_response` + `response_output_to_reply` |
| `ToolCallAccumulator::merge_value/finish` | L140–209 | chat `delta.tool_calls[index]` 语义 | **思想复用、代码不共用**：Responses 的 function_call 增量按 `output_index`/`item_id` 聚合，需写 `FunctionCallAccumulator`（结构照抄：`id/name/arguments` 三段拼） |
| `new/reconfigure/model` | L212–244 | 通用 | trait 化（见 03） |

| `list_models` / `validate`（`chat([user("hi")],None)`） | L252–282 | validate 的探测体是 chat 语义 | `validate` 进 trait；Responses 版用最小 Responses 请求探测 |

| `chat` / `chat_stream` | L315–383 | 强相关 | trait 方法；流循环骨架（SSE 泵 + 冲刷）可抽共享，事件解析按协议分 |
| `apply_stream_line` | L387–447 | chat `choices[].delta` 强相关 | 保留；Responses 写 `apply_response_event`（按 `type` 分发，见 02 §2.4） |
| `SseParser{push,finish}` | L451–493 | **协议无关**（纯 `data:` 切分 + 跨 chunk 缓冲 + `\r\n` 归一） | 原样复用（移到 `llm/sse.rs` 或保持 `pub(crate)` 导出） |
| `probe_models` / `probe_chat` | L496–512 | 向导用 free function | `probe_chat` 需感知协议（按 `Resolved.protocol` 选客户端）；`probe_models` 不变 |
| `truncate` | L514–516 | 通用 | 复用 |

关键回归注释（openai.rs 内原有中文注释，改造时必须保留语义）：
- L66 `ToolRegistry::builtin().defs()` 的 schema 要求 `required` 显式声明，否则部分模型输出空 arguments —— Responses 的 `parameters` 同样要带 `required`，转换时**原样透传** `parameters`。
- `SseParser` 跨 chunk 缓冲（L449–450 的注释）：Responses 流事件更大（function arguments 常分多片），这段复用是正确性关键。

## 1.3 `crates/core/src/config.rs`（约 700+ 行）

- `Config{model,base_url,api_key,provider,providers,context_window,max_turns,persona,build_tag}`：顶层三件套 = 手动覆盖；`providers: HashMap<String,ProviderDef>` 为主存。
- `ProviderDef{base_url,model,api_key_env,api_key,context_window}`：**协议字段加在这里**（`pub protocol: Option<ProtocolKind>`，`None` = chat，见 05）。
- `Resolved{model,base_url,api_key,provider_name,context_window}`：加 `pub protocol: ProtocolKind`（非 Option，有确定默认值，见 05 §5.1）。
- `resolve()`：优先级 CLI > env > 顶层 > provider 预设，`all_providers()` 字段级合并：`protocol` 照抄 `context_window` 的合并口径。
- `save(provider, model, base_url, api_key, context_window)`：签名加 `protocol` 参数；调用点只有 `app.rs` L1200 一处 + 单测。
- `CONFIG_TAG`（`"c6ee35b45916"`）：加字段不触发迁移（`#[serde(default)]` + Option），**不换 TAG**（见 05 §5.4）。
- `env_configured()`：协议 env（如 `ZNAIDE_PROTOCOL`）**不计入**"已配置"判定（它不能独立撑起一次运行）。

## 1.4 `crates/core/src/session.rs`（约 1844 行，引擎）

与 LLM 的触点只有 4 处（其余全是协议无关的工具/历史/UI 逻辑）：

| 触点 | 行 | 说明 | 改造 |
|---|---|---|---|
| `llm: OpenAiClient` 字段 + `Session::new(llm,…)` | L121, L144 | 持有具体类型 | 改为 `Box<dyn LlmClient>`；`new` 签名变，调用点：`cli/main.rs` L275/L294、`tui/app.rs` L301 |
| `reconfigure(&Resolved)` | L204 | `self.llm.reconfigure(resolved)` | trait 方法；切换协议建议 `/clear`（见 06 §6.3） |
| `compact_context` 的 `self.llm.chat(&sum_msgs, None)` | L320 | 摘要请求（无工具） | 经 trait 调 `chat`；Responses 版自动走转换，无感 |
| `run_turn_inner` 的 `chat_stream` / `chat` | L725, L751 | 主循环（stream 有事件时 / 无头无事件时） | 经 trait 调用；`AssistantReply` 形状不变，循环体**一字不动** |

`finalize_assistant`、`repair_tool_chain`、`record`、jsonl 读写：全是 `ChatMessage` 操作，零改动（D4 的收益）。

## 1.5 `crates/tui/src/config_ui.rs`（向导状态机，约 1300+ 行）

- `Step::{Provider,Querying,ModelSelect,ApiKey,ContextWindow,MaxTurns,Verifying}`：新增 `ProtocolSelect`，插在 `ModelSelect` 之后（需求："选完模型名之后"）。
- `SetupWizard{provider,base_url,api_key,model,models,…,context_window,max_turns,…}`：加 `pub protocol: ProtocolKind` + 光标；`draft()` 加协议；`apply_config` / `apply_provider_defaults` 带出协议。
- `on_key` / `confirm_typed` / `render`：每个 `Step` 一处分支，照抄 `ContextWindow`/`MaxTurns` 模式加 `ProtocolSelect` 分支（详情 05 §5.2）。
- `WizardAction::Verify(Resolved)`：`draft()` 已带协议，宿主 `probe_chat` 按协议验证（app.rs L973–979）。

## 1.6 `crates/tui/src/app.rs`（宿主）

- L301 `OpenAiClient::new(resolved)` → 按 `resolved.protocol` 建对应客户端（`build_llm_client(resolved): Box<dyn LlmClient>`，见 03）。
- L963–979 `FetchModels` / `Verify`：`FetchModels` 与协议无关（`GET /models`）；`Verify` 经 `probe_chat` 按协议走。
- L1185–1226 验证通过保存：`cfg.save(…)` 加协议实参；`Reconfigure(draft)` 把协议带给 `Session`。
- L277 `AgentCmd::Reconfigure(Resolved)`、`session.reconfigure(&r)`：签名不变（`Resolved` 多一个字段而已）。
