# 05 — 配置与向导改造

## 5.1 `ProtocolKind` 与 config 结构

```rust
// config.rs 新增
#[derive(Debug, Clone, Copy, PartialEq, Eq, Default, Serialize, Deserialize)]
#[serde(rename_all = "lowercase")]
pub enum ProtocolKind {
    #[default]
    Chat,      // "chat"：POST /chat/completions（现状）
    Response,  // "response"：POST /responses
}

impl ProtocolKind {
    pub fn as_str(&self) -> &'static str {
        match self { ProtocolKind::Chat => "chat", ProtocolKind::Response => "response" }
    }
    pub fn parse(s: &str) -> Option<Self> {
        match s.trim().to_lowercase().as_str() {
            "chat" => Some(ProtocolKind::Chat),
            "response" | "responses" => Some(ProtocolKind::Response), // 复数拼写也认
            _ => None,
        }
    }
    pub fn label(&self) -> &'static str {
        match self {
            ProtocolKind::Chat => "chat（对话补全 /chat/completions）",
            ProtocolKind::Response => "response（Responses /responses）",
        }
    }
}
```

字段落点（D1：按 provider 条目存，与 `context_window` 同口径）：

```rust
pub struct ProviderDef {
    …,
    pub context_window: Option<usize>,
    /// 该 provider 的协议：None = chat（老配置/未填的默认值）
    #[serde(default)]
    pub protocol: Option<ProtocolKind>,
}

pub struct Resolved {
    …,
    pub context_window: Option<usize>,
    /// 确定值（非 Option）：resolve 时已落定，调用方可直接 match
    pub protocol: ProtocolKind,
}
```

`resolve()` 新增入参 `cli_protocol: Option<ProtocolKind>`，优先级（照抄 model 四级口径，再加一级 provider 条目）：

```
CLI --protocol > env ZNAIDE_PROTOCOL > 顶层 config.protocol（新增 Option 字段，手动覆盖）
  > provider 条目 protocol > 默认 Chat
```

- 顶层 `Config` 加 `pub protocol: Option<ProtocolKind>`（`#[serde(default)]`）：与顶层 `model/base_url/api_key` 同为"手动临时覆盖"，`save()` 时清空顶层（见 §5.3），`absorb_top_level_into_provider` 顺手搬它（3 行）。
- `all_providers()` 字段级合并加一段：`if v.protocol.is_some() { base.protocol = v.protocol; }`（照抄 `context_window` 那段 L209–211）。
- `probe_models` 构造的临时 `Resolved`（openai.rs L497–505）加 `protocol: ProtocolKind::Chat`（`GET /models` 与协议无关，随便填 Chat）。

env 名字：`ZNAIDE_PROTOCOL`（值 `chat`/`response`，大小写不敏感，非法值 → 忽略并 `eprintln!` 一句，不 hard fail，避免"换台机器 key 对了却因协议拼写起不来"）。

## 5.2 向导新步骤 `Step::ProtocolSelect`

位置：`ModelSelect`（Enter 选中模型）之后 → `ApiKey` 之前。需求原文"选完模型名称之后"即此。

```rust
pub enum Step {
    Provider, Querying, ModelSelect,
    ProtocolSelect,   // NEW：协议类型（默认 chat）
    ApiKey, ContextWindow, MaxTurns, Verifying,
}
```

`SetupWizard` 新增：

```rust
pub protocol: ProtocolKind,      // 默认 Chat（new() 里 ProtocolKind::default()）
pub protocol_cursor: usize,      // 0=chat, 1=response
```

行为（照抄 `ModelSelect` 的 `↑↓ + Enter` 模式，最简单、无需 typing）：

- 进入：`ModelSelect` 的 `Enter` 分支（config_ui.rs L399–405）选中模型后，`self.step = Step::ProtocolSelect`（原 `Step::ApiKey`），`protocol_cursor` 按当前 `self.protocol` 初始化（重开面板预填时落在已存值上）。
- `ProtocolSelect` 的 `on_key`：
  - `Up/k`、`Down/j`：光标在 2 项之间移动；移动即赋值 `self.protocol = [Chat, Response][cursor]`（所见即所得，免去"选中≠生效"的困惑）。
  - `Enter/e`：`self.step = Step::ApiKey`。
  - `Esc`：回 `Step::ModelSelect`。
- `draft()`：`protocol: self.protocol`。
- `apply_config`：`self.protocol = def.protocol.unwrap_or_default()`（provider 条目值；顶层手动覆盖若有则优先——与 model 的"顶层覆盖预设"口径一致，3 行）。
- `apply_provider_defaults`（切服务商）：`self.protocol = def.protocol.unwrap_or_default()` + `protocol_cursor` 同步（与 `context_window` 那行 L148 同构，避免沿用上一家的协议）。
- render：在模型名下方画两行选项，当前行高亮；附一行说明："chat = /chat/completions（默认，兼容最广）；response = /responses（部分新模型/端点需要）"。
- `confirm_typed`：不受影响（协议步无 typing）。

步骤顺序总览（改后）：`Provider → Querying → ModelSelect → ProtocolSelect → ApiKey → ContextWindow → MaxTurns → Verifying`。`ApiKey` 的 `Esc` 回退目标改为 `ProtocolSelect`（原 `ModelSelect`，L420–427 处改一字）。

## 5.3 保存链路（`Config::save` + app.rs）

```rust
pub fn save(
    &mut self,
    provider: &str,
    model: Option<&str>,
    base_url: Option<&str>,
    api_key: Option<&str>,
    context_window: Option<usize>,
    protocol: ProtocolKind,          // NEW（非 Option：向导永远有确定值）
) -> anyhow::Result<()> {
    …
    entry.protocol = Some(protocol).filter(|p| **p != ProtocolKind::Chat);
    // Chat 存 None（= 默认值）：config.json 保持干净，老版本读新文件也不受影响
    …
    self.protocol = None;            // 顶层清空（与三件套同理）
}
```

- app.rs L1200 `cfg.save(…)` 加实参 `w.protocol`；`draft()` 已带协议 → `Reconfigure` → `Session` 即时生效（06 §6.3）。
- 单测 `max_turns_roundtrip_through_save`（config.rs L619）内的两次 `cfg.save(…5 args)` 补第 6 个参数（`ProtocolKind::Chat`），另加一个 roundtrip 用例：`Response` 存入 → 读回 `Some(Response)` → `resolve().protocol == Response`；`Chat` 存入 → 条目 `None`（干净性断言）。

## 5.4 迁移：不换 `CONFIG_TAG`

- 新增字段全是 `#[serde(default)]` / `Option`：老文件无键 → `None` → chat，行为与改前一致。`needs_migrate`/`migrate` 不动，TAG 不换。
- 顶层 `protocol` 的 `absorb_top_level_into_provider`：在 L433–446 的搬移动作里加 3 行（`if let Some(p) = self.protocol.take() { entry.protocol = Some(p); }`）。注意 `entry.protocol == Some(Chat)` 的语义 = 显式 chat，与 None 等效，`resolve` 时 `unwrap_or_default` 统一收敛，无需清洗。

## 5.5 CLI（`crates/cli/src/main.rs`）

```rust
/// 协议类型：chat（默认）/ response（OpenAI Responses /responses）

protocol: Option<String>,
```

- `cfg.resolve(…, cli.protocol.as_deref().and_then(ProtocolKind::parse))`：`resolve` 签名加第 5 个参数 `cli_protocol: Option<ProtocolKind>`。非法字符串 → `eprintln!` 警告 + 当未传（解析处做，不进 `resolve`）。
- 首跑兜底 `Resolved`（L139–145）：加 `protocol: ProtocolKind::Chat`。
- `config_provided()`：不加 `cli.protocol`（单给协议跑不起来，不算配置）。
- 无头/交互两路的 `OpenAiClient::new` → `build_llm_client`（06 §6.1）。
- `--help` 文案：`about/long_about` 里 env 清单句（L14）追加 `ZNAIDE_PROTOCOL`。
