## 背景

当前全链路只会 `POST {base}/chat/completions`（见 `crates/core/src/llm/openai.rs` 的 `url()` / `build_body()` / `chat()` / `chat_stream()`）。
不少 OpenAI 兼容端点与新模型只暴露 Responses 语义（或在 Responses 下工具调用更稳），用户需要"同一套配置、两种协议可切换"。

## 需求原文

1. 初始化向导：选完模型名称之后，加一步协议类型选择，默认 `chat`，可选 `response`。
2. 完整适配 response 协议内容，尽量复用已有代码。

## 目标（做什么）

- T1：配置层新增"协议类型"（`chat` / `response`），按 provider 条目存储，`Resolved` 随身携带。
- T2：向导在"模型选择之后、ApiKey/验证之前"插入协议选择步，默认落 `chat`。
- T3：新增 Responses 客户端（请求构造、非流式解析、SSE 流式解析、工具调用），与现有 `OpenAiClient` 共享：`SseParser`、容错解析、`Usage`、`ToolCallAccumulator` 思想、`proxy_from_env`、`truncate`、超时配置。
- T4：`Session` 引擎经 `LlmClient` trait 同时支持两种协议：主循环、工具执行、`compact` 摘要、`validate` 探测全部打通。
- T5：CLI（`--protocol` + env）与历史会话兼容（老 jsonl 无协议标记照常读）。

## 非目标（不做）

- 不做 Responses 特有高级能力首版接入：`previous_response_id` 服务端状态链、`store/background`、`reasoning.effort` 调参面板、`max_output_tokens` 独立配置。这些在数据模型里预留字段，不在首版暴露 UI。
- 不做"同一会话内中途换协议"的消息格式迁移（换协议提示用户 `/clear` 或开新会话；见 06）。
- 不重写现有 chat 链路的任何行为：chat 回归零差异是硬要求。

## 核心决策一览

| # | 决策 | 结论 | 理由 |
|---|---|---|---|
| D1 | 协议归属粒度 | **按 provider 条目存**（`ProviderDef.protocol`），与 `context_window` 同口径 | 切 provider 时协议跟着走，避免"新端点 + 老协议"错配；顶层保留手动覆盖 |
| D2 | 默认值 | **`chat`** | 现状零回归；老配置无标记 → chat |
| D3 | 抽象方式 | 新增 `LlmClient` trait（`chat` / `chat_stream` / `validate` / `list_models` / `model()` / `reconfigure`），`OpenAiClient` 与 `ResponsesClient` 各自实现，`Session` 持有 `Box<dyn LlmClient>` 或泛型 | 调用方（`session.rs`、`app.rs`）改动面最小；两种协议可独立演进 |
| D4 | 历史兼容 | `ChatMessage`（chat 语义）仍是**内存 + 落盘**的唯一格式；Responses 只在"发请求前一刻"转换 | 老 jsonl 零迁移；`repair_tool_chain`、`compact`、恢复逻辑全部不用动 |
| D5 | 工具结果回填 | 内存里仍记 `ChatMessage::tool`；发 Responses 请求时翻译成 `function_call_output` item | 同 D4，执行层（`execute_tool_call`）零改动 |
| D6 | 端点 URL | `{base}/responses`（`base_url` 的 `/v1` 后缀原样保留，只换 path 尾段） | 与 `url()` 的 `trim_end_matches('/') + "/chat/completions"` 对称 |

## 验收标准

- A1：全新初始化走完向导，`config.json` 对应 provider 条目里有 `"protocol": "chat"|"response"`，缺省为 `chat`。
- A2：老配置（无 `protocol` 键）加载、resolve、运行行为与改前一致（chat）。
- A3：`response` 协议下：纯文本问答、流式增量显示、多工具连调、`compact`、`/config` 重配、`--resume` 恢复均可用。
- A4：`cargo test` 全绿；新增 mock Responses 服务器集成测试覆盖：文本流、function_call 流、usage、错误。
- A5：chat 链路无行为变化（`git diff` 不碰 `parse_chat_response` / `apply_stream_line` 逻辑，只做必要的共享抽取，且抽取后单测照常通过）。
