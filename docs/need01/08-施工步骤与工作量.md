> 顺序按依赖排：每阶段结束 `cargo test` 全绿。预估总量约 1300–1600 行新增（含单测），chat 旧逻辑 0 行改动（只有"移动"）。

## 8.1 分阶段施工

### P0 基线（0.5 天）
- `cargo test` 跑绿，记录基线。
- 无代码改动。

### P1 共享抽取 + trait（1 天）
文件：`llm/sse.rs`（新建，搬 `SseParser`）、`llm/client.rs`（新建，trait + `build_llm_client` + `http_error`/`truncate`/`new_http_client`/`auth` 抽取）、`llm/mod.rs`、`llm/openai.rs`（删搬走的代码，`impl LlmClient for OpenAiClient` 薄转发）。
- 验收：`cargo test` 全绿（搬家前后行为一致）；`Session` 仍用 `OpenAiClient`（P2 再换），先只验证 trait 编译通过。

### P2 Responses 客户端（2–3 天，主体）
文件：`llm/responses.rs`（新建，§3.5 结构 + §7.2 单测）。
- 先非流式（`build_response_body` + `chat_to_response_input` + `parse_response_response`），再流式（`FunctionCallAccumulator` + `apply_response_event` + `chat_stream`）。
- 验收：§7.2 单测全绿；`cargo test` 全绿。

### P3 配置（0.5–1 天）
文件：`config.rs`（`ProtocolKind` + 3 处字段 + `resolve` + `save` + `absorb` + `all_providers` 合并 + 单测）。
- 验收：§7.4 config 用例全绿；老 config.json（删掉 protocol 键的手工 fixture）加载行为不变。

### P4 会话引擎（0.5 天）
文件：`session.rs`（`Box<dyn LlmClient>` + `Session::new` 签名 + `reconfigure` 协议切换 + `describe_request_error` 两条文案）、`llm/mod.rs` 重导出（`AssistantReply` 等保持 import 零改）、`mock_e2e.rs` 追加 §7.3 用例。
- 验收：§7.3 集成测试全绿；chat 旧集成用例全绿。

### P5 向导 + 宿主 + CLI（1–1.5 天）
文件：`config_ui.rs`（`Step::ProtocolSelect` + 状态 + `on_key` + `draft`/`apply_*` + render + 单测）、`app.rs`（`build_llm_client` + save 实参 + Notice 文案）、`cli/main.rs`（`--protocol` + env + 兜底 Resolved）。
- 验收：§7.4 向导用例 + §7.5 手工清单。

### P6 联调与文档收尾（0.5 天）
- 真端点跑 §7.5 清单（至少一个 Responses 可用端点 + ollama chat 回归）。

- `cargo build --release` 确认 release profile（`panic=abort` + lto）下编译无警告新增。

## 8.4 风险与对策

| 风险 | 概率 | 对策 |
|---|---|---|
| 兼容端点 Responses 实现与标准有出入（字段名/事件名） | 高 | 解析层全部容错 + 忽略未知（§4.3）；联调时按实际端点补分支，单测锁定 |
| 某端点 `/responses` 与 `/models` base 路径不一致 | 中 | `url()` 只换 path 尾段；若实测需特殊规则（如不带 `/v1`），在 `ResponsesClient::url` 里单独处理，不碰 chat |
| `async-trait` 引入 vs 手写 Future | 低 | P1 定：优先手写 `Pin<Box<dyn Future>>`（零新依赖）；若影响可读性则加 `async-trait`（workspace 一行） |
| 向导步骤加一处导致 `/config` 老用户迷路 | 低 | 默认光标落在 chat（回车即过），多按一次回车而已；render 首行注明"默认 chat，直接回车跳过" |
| 流式断流无 `completed`（无 usage） | 中 | 与 chat 现状一致（usage 为 0 时不累计、不发事件，L756 `is_empty` 已处理）；不断言 usage 必达 |
